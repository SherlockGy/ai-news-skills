# 开发维护透镜

## 适用目标

仅用于开发者维护基准模板、lint 规则、Go CLI、跨平台构建产物和本 skill 路由。普通新闻生成不得进入本透镜。

## 修改前闸门

1. 通读待修改文件及其直接关联测试，确认变更属于模板视觉、lint、CLI、构建或路由中的哪一层。
2. 模板位于 `go-cli/assets/news-page-template.html`，是唯一页面外壳；不得增加普通生成可选择的模板参数。
3. 修改公共函数或命令契约前先搜索全部调用方与测试。超出本 skill 的影响必须先告知用户。
4. 发现规则分散、重复冲突或补丁式维护时，先做结构化重整，不继续叠加局部例外。

## 维护闭环

1. 按职责修改：
   - 路由与全局边界放在 `SKILL.md`。
   - 普通执行规则放在 `flows/generate.md`。
   - 开发、自检、构建规则保留在本文件或 `go-cli/README.md`。
   - 模板、解析和 lint 实现放在 `go-cli/`，不得复制到透镜。
2. 修改模板时保留自然标题换行基线：

   ```css
   text-wrap: pretty;
   word-break: normal;
   line-break: strict;
   overflow-wrap: break-word;
   ```

   禁止加入 `text-wrap: balance`、手工断行元素、不换行空格或零宽字符。
   标题断点必须由 `Intl.Segmenter` 的通用词边界、标点优先级和浏览器实际宽度共同计算；不得按固定字数重新拼块，也不得依赖需要穷举的业务词典。`：:`、`，,` 后是高优先级候选，单个汉字两侧的断点必须增加惩罚。
3. 运行 `go test ./...`，所有对外参数、非法组合、零副作用、CJK 强调、正文保真和模板规则测试必须通过。
4. 从任意工作目录调用构建脚本并核对三项 amd64 产物：
   - Windows：`go-cli/scripts/build.ps1`
   - Linux 或 macOS：`sh go-cli/scripts/build.sh`
5. 分别使用日报和周报长篇新闻稿完成 `build` 与独立 `lint`；周报覆盖任意星期起止、跨月和跨年范围。重复构建一次，确认输出自动使用 `-2` 避让。
6. 只有模板、CSS 或浏览器脚本发生变化时，必须先用 `testdata/title-wrap-regression.md` 生成回归页，通过本地 HTTP 打开，再使用外部 Playwright MCP 执行 `scripts/playwright-title-regression.js`。脚本自动覆盖 `1440×900`、`390×844` 及移动端最大字号，并检查：
   - 标题断行自然，没有孤立标点或人为断点。
   - 覆盖含 `：:`、`，,`、中英文混排和未知复合词的长标题，确认优先在标点后断行，且不会留下单个汉字。
   - 页面没有横向溢出。
7. 再使用用户提供的长篇新闻稿，通过外部 Playwright MCP 检查目录、字号、纸色和移动端抽屉可用。
   - 浏览器运行时不可用时明确报告未完成视觉验收，不得以静态检查冒充通过。
8. 执行普通生成透镜的完整回归口径后再交付。

## CLI 自监督

- 命令契约保持为 `build --report-type --source --output`、`lint --report-type --source --page` 和 `version`；`--report-type` 必填且只允许 `daily`、`weekly`。新增或删除参数必须重新取得用户确认。
- 日报与周报规则必须按 `--report-type` 分支独立维护，不得为了兼容周报而放宽日报规则，也不得根据日期跨度静默推断模式。
- 单值参数重复、未知参数、多余位置参数及帮助参数与业务参数混用必须在任何文件写入前失败。
- `build` 只创建新文件并自动避让，不提供覆盖和 dry-run；写入后必须同步、回读并执行最终 lint。普通失败清理本次文件，清理失败时报告残留路径；不得承诺进程强制终止或机器断电后一定无残留。
- 不开发面向调用方的本地删除能力，绝对禁止递归删除。
- 完整 HTML 写入文件，终端只输出有界摘要；lint 最多展示前 100 条诊断并报告总数。
- 修改模板、命令、诊断代码或输出字段时同步帮助、测试、`flows/generate.md` 和 `go-cli/README.md`。
- 新增场景前重新判断是否仍是单业务链；出现多模板、多输出或多渠道时先向用户提出结构重审。

## 路由与描述自检

- `SKILL.md` 必须保持薄，并继续要求打印“走 X，依据：...；下一步读取 ...”。
- description 只写触发条件，不写实现步骤。
- 新增、移动或重命名文件后检查每份执行文档都有唯一上游入口，无并读拼装和链外执行文件。
- 维护说明保持简短、稳定，不把调试记录、代码考古或一次性命令写入执行路径。
