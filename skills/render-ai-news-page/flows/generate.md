# 普通生成透镜

## 适用目标

把用户独立提供的完整新闻文本生成固定模板单页面 HTML。新闻可以来自用户提供的文件、当前消息或当前 Agent 上下文；本透镜不搜索新闻、不修改模板，也不执行开发期 Playwright 验收。

## 输入边界

- 必须取得完整新闻文本和目标 HTML 路径。输入可以是现成 Markdown 文件，也可以是当前消息或上下文中边界明确的完整正文。
- 输入不是现成 Markdown 文件时，先保存为 UTF-8 `.md` 中间稿：
  - 已有 Markdown 结构时原样保存。
  - 普通文本只补充生成必需的标题层级、列表或引用标记，不改写词句，不调整段落顺序，不总结或删减内容。
- 当前上下文存在多段候选文本、无法唯一确认正文范围时，先请用户确认；不得自行拼接。
- 未提供目标路径时先询问用户，不猜测目录。
- 必须确定报表类型并映射为 CLI 参数，不得根据日期跨度静默推断：

  | 用户目标 | `--report-type` | 独立格式规则 |
  |----------|-----------------|--------------|
  | 日报、单日新闻 | `daily` | 报刊标题后是“生成日期/生成时间”段落；至少一个正文一级章节；首个二级标题是“今日思想亮点” |
  | 周报、日期范围新闻 | `weekly` | 报刊标题后是“日期范围/统计周期”段落或引用块；只用首个一级标题作为报刊标题；首个二级标题是“本周判断”，其后至少一个二级正文章节 |

  周报只校验有效起止日期和先后顺序，不限制从星期几开始、到星期几结束，也不要求固定天数。用户目标无法确定是日报还是周报时先询问，不得用源稿日期格式代替用户选择。
- 本 skill 不判断新闻事实、观点、日期事实或内容质量；CLI 只校验可机械确认的文件、Markdown 与页面格式。

## 执行闭环

1. 确认完整输入范围并取得可供 CLI 读取的 UTF-8 `.md` 路径。现成 Markdown 文件无需为了事实或内容审查而通读；结构问题交给 CLI 诊断。
2. 确认环境中可用 Go 1.25 或更高版本。普通生成直接使用随 skill 分发的 Go 源码，不依赖预编译二进制。
3. 在 `go-cli/` 目录执行：

   ```text
   go run ./cmd/render-ai-news-page build --report-type <daily|weekly> --source <新闻稿.md> --output <目标.html>
   ```

   - `--report-type`、`--source` 与 `--output` 均必填且只能出现一次。
   - `--report-type` 必须与用户要求一致；日报传 `daily`，周报传 `weekly`。模式不匹配时不得改用另一模式绕过 lint。
   - 目标文件已存在时，CLI 自动使用 `-2`、`-3` 后缀避让；不覆盖已有文件。
   - CLI 在内存中完成生成和 lint，通过后才创建新文件；写入后会同步、回读并执行最终 lint。
   - 普通写入或最终 lint 失败时会清理本次新建文件；若清理也失败，错误会明确报告可能残留的路径。进程被强制终止或机器断电不属于可保证清理的范围。

4. 仅在命令返回 `状态: 成功` 且 `lint: 通过` 后交付实际输出路径。
5. 交付时报告源稿路径、实际 HTML 路径、源稿 SHA-256、模板 SHA-256 和 lint 结果。

## 结果与失败口径

- 退出码 `0`：生成或校验成功。
- 退出码 `2`：命令、参数或控制模式错误；修正调用方式后重试。
- 退出码 `3`：源稿、模板或页面 lint 失败；按诊断修正源稿，普通生成不得修改模板或 CLI。
- 退出码 `4`：文件读取、生成或写入失败；报告原始错误和涉及路径，不宣称已生成。
- Go 1.25+ 不可用或依赖无法取得时停止并报告环境问题；不得临时改用 Python 或现场重写 HTML。

## 禁止事项

- 不调用搜索、网页或知识库补充新闻。
- 不直接编辑生成后的 HTML。
- 不使用 `<br>`、`<wbr>`、不换行空格或零宽字符调整标题换行。
- 不增加覆盖、删除、批量生成或自定义模板参数。
