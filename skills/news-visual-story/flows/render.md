# 生图与复核透镜：分镜 JSON 到可交付图片

## 适用

- 分镜 JSON 已检查 PASS，要生成图片。
- 图片已生成，要逐帧复核、返修个别帧、整理交付目录。

进入本透镜后不回读 `SKILL.md`。本文件包含生图、复核、返修、交付的全部规则。

## 入口判别

| 现状 | 走法 |
|---|---|
| 有 JSON，检查 PASS，无图片 | Step 1 起完整执行 |
| 有 JSON，有图片 | 跳过 Step 2 的生成，从 Step 3 复核起 |
| 有 JSON，检查未 PASS | 停下，回叙事分镜透镜先检查 |
| 只有图片，没有 JSON | 停下问用户 JSON 在哪；没有则回叙事分镜透镜从头做 |

判别后回复一句「走生图与复核，现状：<上表哪一行>；交付目录：<路径>」。

## 硬约束

- 生图只用当前会话的图像生成工具。本 skill 不含生图脚本。
- 每帧 Prompt 必须是 JSON 里 `frames[].prompt` 的全文，不现场改写、不删块、不补句。
- 不请求透明背景。工具有透明或 alpha 开关时显式关闭。
- 复核只拦语义错误：数字错、关系看不出、方向反、图标暗示原文没有的意思、画面加入分镜明确省略的内容。表头颜色、字号、系列标记样式、构图取舍这类风格差异只记录，不返修。
- 模型自行加的元素，只要忠于原文、有用且未在 `omitted` 登记，保留。图上多出的有用文字以图为准回填 JSON 文字槽并重跑脚本，不重生成。不得为了让图和 TEXT 块逐字一致而删掉有用的东西。
- 只重生成有语义错误的帧。同一帧返修超过 3 轮仍不通过，停下把问题和候选处理交给用户。

## Step 1 交付目录

交付目录由用户指定，未指定时问。一条新闻一个目录，不混。

```text
<交付目录>/
├── <story.id>.json        分镜 JSON，与生图时使用的版本一致
├── <NN>-<question>.png    每帧一张，文件名用序号加该帧第一个 question
├── review.md              逐帧复核记录，见 Step 5
├── README.md              阅读顺序与检查口径，见 Step 6
└── _drafts/               被返修替换的旧版本，文件名加 -draft-N
```

## Step 2 逐帧生成

按 `index` 顺序逐帧：

1. 取该帧 `prompt` 全文传给图像生成工具。比例 16:9，尺寸 1920×1080。工具不支持指定尺寸时记录实际输出尺寸。
2. 生成后立即按 Step 3 复核本帧，不要先生成全部再一起看。
3. 在 `review.md` 记录本帧：工具、尝试次数、通过或问题项。

## Step 3 逐帧复核清单

每帧逐项核对，任一语义项不通过即进入 Step 4。

| # | 检查项 | 怎么核 | 通过标准 | 类型 |
|---|---|---|---|---|
| 1 | 尺寸 | 读 PNG 头，命令见下 | 1920×1080；做不到时记录实际尺寸 | 记录 |
| 2 | 文字 | 图上文字与 `[TEXT]` 块逐条对照 | 不少字、不错字、不重复。多出的字若忠于原文、有用且未在 `omitted` 登记，回填 JSON 后算通过 | 语义 |
| 3 | 数字 | 对照原文 | 画了的数字正确，带单位和比较对象 | 语义 |
| 4 | 关系可见 | 盖住标题看画面 | 能看出 `visual.relation` 那种关系 | 语义 |
| 5 | 方向一致 | 标题与画面并看 | 画面方向不与 headline 相反 | 语义 |
| 6 | 图标含义 | 逐个看图标 | 没有暗示原文没有的意思；`avoid` 里的项没出现 | 语义 |
| 7 | 内容取舍 | 对照 `reading.omitted` | `omitted` 登记的内容没有被模型加回画面 | 语义 |
| 8 | 元素完整 | 看箭头、连线、主角 | 箭头有起止，循环闭合，主角有身份标识 | 语义 |
| 9 | 固定风格 | 看整体 | 米白不透明底，无渐变、霓虹、3D；其他风格差异只记录 | 记录 |

像素尺寸命令，无第三方依赖：

```bash
python -c "import struct,sys;h=open(sys.argv[1],'rb').read(24);print(struct.unpack('>II',h[16:24]))" 01-what.png
```

## Step 4 返修

| 问题类型 | 修法 |
|---|---|
| 多了忠于原文、未在 `omitted` 登记的有用文字 | 回填 JSON 对应槽位，重跑 `python scripts/check_storyboard.py`，不重生成 |
| 多了无用文字、错字、重复 | 在 `avoid` 加具体项，重生成 |
| 数字错或缺单位比较对象 | 改 JSON 文字槽，重跑脚本后重生成 |
| 关系看不出 | 改 `visual.relation` 或 `composition`，重生成 |
| 方向相反 | 先判断是 headline 措辞还是 composition 的问题，改对应字段，重生成 |
| 图标暗示原文没有的意思 | 在 `avoid` 加具体项，重生成 |
| 模型自行加入 `omitted` 内容 | 在 `avoid` 加具体项，重生成 |
| JSON 槽位与 `omitted` 冲突 | 回叙事分镜透镜修正取舍，重跑脚本后重生成 |
| 箭头悬空、主角无身份 | 在 `composition` 写明连接关系与身份标识，重生成 |
| 只是风格不一致或尺寸不足 | 记录在 review.md，不返修 |

重生成后：

1. 旧版移入 `_drafts/`，文件名加 `-draft-N`。
2. 重新过一遍 Step 3 全部 9 项，不只看被修的那项。
3. 与旧版并排对比，确认非文字元素没有丢失。

## Step 5 review.md

逐帧一节：

```markdown
## 帧 N：<questions>

- 文件：`0N-<question>.png`
- 工具：<图像生成工具名>
- 尝试：<次数>
- 尺寸：<实际尺寸>
- 清单：1 记录 / 2 通过 / 3 通过 / … / 9 记录
- 问题：<不通过项，无则「无」>
- 回填：<从图回填到 JSON 的内容，无则「无」>
- 处理：<返修动作，无则「无」>
- 待确认：<需用户决定的事项，无则「无」>
```

结尾一节「40 秒测试」：只看图不看原文，按第一帧选择的叙述路径检查：

- 第一帧含 `what`：先写下发生了什么，再复述后续帧实际提供的重要性、关系或意义。与 `story.what` 和后续帧的 claim 对照，`null` 字段不要求回答。
- 第一帧含 `insight`：先写下核心判断，再复述后续帧实际提供的依据、关系或实践动作。与 `story.insight` 和后续帧的 claim 对照，`null` 字段不要求回答。

对得上写「通过」，对不上写哪一项没对上、哪一帧要改。有同事在场就让同事答。

## Step 6 README.md

交付目录 README 只写四件事：

- 来源原文与新闻标题。
- 阅读顺序，一行一帧，写 headline。
- 检查口径：脚本 PASS 表示格式检查通过；逐帧语义复核与 40 秒测试见 review.md。
- 文件清单。

## 收尾

回复一句「生图与复核完成：N 帧通过，40 秒测试 <通过或哪一问未过>，待确认 K 项；review.md 与 README.md 已写入 <交付目录>」。
