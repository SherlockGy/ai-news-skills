# 新闻图文叙事

## 行为覆写

这套图给没读原文、时间很少的同事看。40 秒内先让他知道这组图在讲什么，再看懂其中最有解释价值的事实、关系和实际意义。事件新闻从发生了什么起，洞见内容从核心判断起。图不是文字的插图，是文字的替代品。

- 收到任务后必须先按下面的意图表选透镜，再读取对应 `flows/*.md` 并按其流程执行。
- 选定透镜之前，不得写阅读层、不得分镜、不得拼 Prompt、不得调用生图工具、不得改任何文件。
- 一次只做一条新闻。输入含多条新闻时，先列清单让用户挑；用户明确说全做，也按顺序逐条做，每条交付并复核完再开始下一条。
- 意图表里有 2 行以上沾边，或一行都不沾边，停下来问用户，不默认走综合。
- 本文件不承载执行方法。字段定义、写法规则、检查清单都在透镜里。

## 产物链

```text
一条新闻文本
   │  flows/storyboard.md   阅读层 → 安排每张图讲什么 → 文字与画面 → Prompt → 脚本检查
   ▼
分镜 JSON
   │  flows/render.md       逐帧生图 → 复核 → 返修 → 交付目录
   ▼
1 到 5 张图 + review.md

固定资料  assets/   Prompt 固定块与渲染契约，透镜逐字引用，不得改写
```

## 边界

- 忠实指画上去的每句话能回到原文，原文的主判断不被换掉。段落可以省，省了在阅读层记一笔。不为多条新闻归纳原文没有的共同主线。
- 摘要和洞见用原文现成的句子。原文有一句话摘要就原样上图，不自己总结。
- 先确定内容对象，再用有限画面选择最能增加理解的事实和关系。限制、代价、截止日期等信息与其他内容按同一标准取舍。只调整语气的兜底表达不上图。决定内容性质的事实状态随主句表达，不单独做提醒。
- 生僻名称和缩写在图里用一句话解释，可用常识。判断标准是产品经理看不看得懂。
- 生图由当前会话的图像生成工具执行。本 skill 不建叠字工具，文字由生图模型渲染。复核只拦语义错误，风格差异不返修。
- 脚本只查字段、格式、固定块和字数，不判断内容。

## 意图识别

**先通读全表，再选透镜。**

| 意图信号 | 透镜 | 文件 |
|---|---|---|
| 给一条或一篇新闻文本，要配图、可视化、图文叙事、分镜、生图提示词；或已有分镜 JSON 要改后重查 | 叙事分镜 | [flows/storyboard.md](flows/storyboard.md) |
| 分镜 JSON 已检查通过，要生成图片；或图片已生成，要逐帧复核、返修个别帧、整理交付目录 | 生图与复核 | [flows/render.md](flows/render.md) |
| 改本 skill 的规则、固定块、JSON 字段、字数目标、检查脚本、触发描述 | 维护 | [flows/maintain.md](flows/maintain.md) |

选定透镜后，回复一句「走 X，依据：用户提到 <原话片段>；下一步读取 <文件>」，然后读取对应文件并按其流程执行。在此之前不得调用工具、不得开始执行。

## 常见误路由

- 用户给了图片但没有分镜 JSON：不是生图与复核。先问 JSON 在哪，没有就走叙事分镜从头做。
- 用户给整篇日报：走叙事分镜，但第一步是列清单让用户挑一条，不是把全篇切开。
- 用户要「归纳今天的主线」「几条新闻放一张总览」：本 skill 未建总览帧，说明后停下。
- 用户要深挖某个概念做一组解释图：本 skill 只在图内做一句话解释，深挖未建，说明后停下。
- 用户只说「检查一下」：给的是 JSON 走叙事分镜的脚本检查步骤；给的是图片走生图与复核。
