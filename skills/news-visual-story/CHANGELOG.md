# Changelog

## v1.6 — 明确省略清单交接

- 内容取舍在分镜阶段确定并登记到 `omitted`；渲染阶段按清单检查，不重新判断兜底表达。

## v1.5 — 通用化 footnote

- `footnote` 根据当前帧需要使用，出现位置和来源字段由该帧内容决定。

## v1.4 — 简化重点判断

- 第一张负责让读者进入正确上下文，后续选择能加深理解的内容，不要求都直接解释第一张。
- 内容根据其对内容对象的解释价值取舍。限制、代价等信息与其他内容使用同一标准，语气性兜底省略，事实状态随主句表达。
- 渲染复核只检查分镜已经确定的取舍，不按正面或负面重新分类。画面校验改为判断语义关系，删除具体新闻句式和画面例子。

## v1.3 — 按内容选择叙述路径

- 分镜期增加事件新闻与洞见内容的二级语义路由。事件从发生了什么起，洞见从核心判断起，两条路径共用后续画面、Prompt、生图与复核流程。
- 原文缺少非起点信息时允许显式留空并减少帧数，不用相关性弱的内容补齐结构；缺失影响理解时由用户选择补充调查或保留现状。

## v1.2 — 分离格式与内容

- Prompt 和 JSON 说明改为字段与类型契约，执行透镜不再用具体新闻内容演示格式；完整实例只保留在测试中。

## v1.1 — 调整表达

- 删除抽象称呼，统一改用“安排每张图讲什么”等直接描述；字段和执行规则未变。

## v1 — 从目的重建

- 目的定为：给没读原文、时间很少的同事看，40 秒内知道谁、发生了什么、为什么重要、怎么回事、所以呢。
- 内容按读者获取信息的顺序安排：先讲发生了什么，再讲重要性，以及原文提供的机制、结构或边界，最后给出原文洞见。一条新闻 3 到 5 张，第一张放原文一句话摘要，最后一张放原文洞见。
- 分镜前先写阅读层：who、what、why、insight、术语表、省略清单、顺序说明。
- 忠实的定义改为：画上去的每句话能回到原文，主判断不被换掉。段落可以省，省了记一笔。
- 图上只放肯定句。反向信号与兜底信号不上图，登记到省略清单；解释「怎么回事」的适用范围可以上图。
- 术语在图内一句话解释，每帧最多两条，判断标准是产品经理看不看得懂。
- 一次只做一条新闻，输入多条时先列清单让用户挑。
- 生图由会话内图像工具执行，不建叠字工具。复核只拦语义错误，风格差异不返修，模型自行加的有用元素回填 JSON。
- 脚本只查字段、枚举、序号、Prompt 六块拼装，字数与帧数只提醒。不判断内容，不判断措辞，不判断是否指向原文。
- skill 不含样例，JSON 结构以 `flows/storyboard.md` Step 7 为准。
- 视觉身份为米白五色编辑部信息图风格与固定版式；版式块容纳摘要段落和术语解释。
